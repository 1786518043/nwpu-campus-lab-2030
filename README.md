# 2030 校园实验室 · 西工大双校区

以西北工业大学长安校区和友谊校区为地图场景的绿色校园决策原型。所有预算、碳排放和体验数值均为教学设定，不代表学校实际数据。没有接入实时 AI，没有账号和远程业务服务。

## 运行

本机已经安装依赖。双击根目录的 `启动校园实验室.cmd` 可以启动并打开浏览器。

标准开发环境（Node.js 22+、pnpm 11+）也可运行：

```sh
pnpm install
pnpm dev
```

默认地址 http://127.0.0.1:5173/ 。如提示端口已被占用，请先查看该地址是否为已有的本项目服务。开发服务仅监听本机。

手机体验：双击 `手机预览校园实验室.cmd`，或运行 `pnpm preview:phone`。脚本先生成生产构建，再在电脑当前有默认网关的网卡地址上启动静态预览，显示类似 `http://192.168.31.129:4173/` 的链接。手机和电脑须连接同一 Wi-Fi，手机打开脚本显示的地址；`127.0.0.1` 在手机上指手机自身。电脑及预览进程须保持运行，换网络后重新启动以获取新地址。该入口不进行公网部署，不能通过蜂窝网络直接访问。

如同一 Wi-Fi 仍连接失败，检查 Windows 防火墙是否允许当前局域网访问 TCP 4173，以及 Wi-Fi 是否使用访客/设备隔离。手机预览脚本不自动修改防火墙或网络安全设置。局域网预览使用构建结果，代码更新后需重新运行。不同设备、不同地址的浏览器存档相互独立，可导出结果备份。

```sh
pnpm test
pnpm build
pnpm preview
```

`dist/` 为生产构建。GitHub Pages 发布流程见 `.github/workflows/pages.yml`：推送 `main` 后自动安装锁定依赖、执行测试、构建并部署；仓库 Settings → Pages 的 Source 应设为 GitHub Actions。更新是否上线以 Actions 的部署结果为准。本机文件修改不会自动推送。Vite 和参考图片使用相对于站点的路径，可部署在仓库子目录或域名根目录。

公网访问无需本机保持开机，各访问者的实验进度保存在自己的浏览器中。更换域名后旧地址的浏览器存档不会自动迁移，可在旧地址导出结果备份。此前的 Sites 配置保留在 `.openai/hosting.json`，GitHub 工作流不会更新或依赖该站点。

## 建筑规划怎么玩（V 0.4）

保留原有 Three.js 精细校园作为唯一规划主视图。网格只参与后台运算，页面不展示格线、格子编号或选格操作。

1. 点击三维楼体，或搜索、选择建筑。所选楼体高亮，可近看立面、屋顶、中庭与施工状态。无法使用 WebGL 时仍可通过建筑列表配置。
2. 按整栋建筑选择措施。光伏、节能改造覆盖完整轮廓；同一 OSM 关系的多个体块，以及名称明确关联的教学东楼、海天苑大楼、启翔楼等楼翼统一作为一个实施单位。原始模型几何不改动。
3. 花园、照明、慢行和接驳归属于建筑，后台选择附近符合条件的开放地表或道路。不能占水体、球场、施工区；同一公共设施若已由邻楼配置，可共享服务，不能重复购买。
4. 确认前查看投入与边际效果。花园和慢行有协同，慢行与接驳可连通，照明和站点可能影响生态安静与宿舍；原有距离衰减、重复覆盖、天气与预算规则继续有效。
5. 保存建筑方案 A，再调整 B。两份方案共用事件和预算，切换 A/B 时三维设施同步显示；超预算方案保留但不能另存为可行方案。
6. 导出包含建筑名、建筑 ID、措施、实施范围、内部空间属性和计算结果的 JSON，便于复现。

教学挑战保持：100 建设点内，同情境减排至少 2%、体验提高至少 1、模拟活动需求覆盖至少 12%；预算收紧为 80 点。两个校区均有经过测试的可行建筑方案。

## 建筑与内部空间计算

- `src/buildingPlanning.ts` 将完整建筑多边形与内部约 40 米单元做面积裁切并扣除中庭。小于单元的建筑也可以独立选择；相邻建筑共享内部单元时，仍按各自轮廓贡献分别计算建筑用能与减排。
- 每个建筑单位对应一个措施记录，不让用户逐格拼楼。关联楼翼作为同一单位，但原立面、连廊、屋顶设备与施工模型保留。
- 建筑节能和光伏成本采用体量函数：基础单价 × (0.45 + 0.55 × √(建筑面积 / 内部单元面积) + 0.06 × 模型高度)，四舍五入、最低 6 点。均为教学预算，非工程造价。
- 慢行选择楼旁相连的已有路段，最多覆盖四个内部路段单元，按 8 点/单元计价。花园选择距建筑边界约 60 米内可用地表；照明和慢行约 70 米、接驳约 80 米内匹配候选位置。这是可用位置近似，不是核验过的真实出入口。
- 花园影响半径约 120 米，慢行/照明约 80 米，站点约 100 米。影响随距离线性衰减，同类服务取较强值。接驳通过已有车辆路网寻路，不使用步道、台阶；未连通站点不产生服务。
- 每栋建筑先节能，再用光伏抵扣剩余用能。节能系数 0.65（高温 0.55）；光伏抵扣受日照代理与天气系数限制，不能把邻楼的剩余用能也一起抵扣。照明、线路运行另计耗能。
- 全校排放相对常态空白方案归一化；体验、压力和覆盖按模拟活动需求加权。覆盖表示体验改善至少 1 点或本地用能降低超过 8%，不是实际服务人数。
- 人流需求、日照、未识别空地比例、建筑高度和各种作用系数均为教学估算。没有地形高程或管网，不模拟真实汇水方向。固定输入和事件得到固定结果，次序不改变结果、事件不累计。

## 存档兼容

V 0.5 增加所选措施的三维影响预览，沿用 V 0.4 的分数和版本 3 存档。蓝色柔和光晕表示距离作用范围，建筑轮廓与标签分别用绿色（正面）、红色（负面）和琥珀色（利弊并存）解释增量影响，不展示计算网格。几何模型和来源不变。

- 新措施比较“当前方案”与“增加这一项”；已实施措施比较“移除这一项”与“保留这一项”。A 只分析 A 内已有措施，共用当前天气；预览不写入措施或预算。
- 两侧都从初始状态重算，所以包含花园与慢行、照明与花园、站点与宿舍的协同/代价和重叠收益递减。正负分项分别显示，净体验提高不会掩盖噪声、光扰动或用能代价。
- 范围半径直接使用空间引擎的参数，连通站点与末端慢行的间接启用区域也展示。孤立站点仅显示灰色潜在范围，无出行收益；线路运行能耗单列，不强行分配到邻楼。
- 屋顶和节能措施的新配置只归因到所选整栋建筑。同一计算单元内的邻楼不会被标成获得本栋屋顶改造。旧配置保留原范围并提示。
- 周边指标按建筑轮廓及楼外约 40 米范围内的模拟需求加权。周边用能展示该评价区域的相对变化；其他分项为模型指数。相邻建筑共享环境，不可把这些区域指标相加。图上连续光晕是作用范围示意，不是实测物理边界或工程预测。
- 点击影响标签或下方建筑卡可查看明细、定位邻楼，保留原措施选址。可隐藏影响恢复纯模型，也可一键查看影响全貌。

V 0.4 使用版本 3 的建筑存档，两个校区仍各自使用原键名。V 0.1–0.3 的措施位置、事件及 A/B 都会迁移：原实施范围保存在建筑记录的 `legacyCells` 内，按最近建筑归类，页面标记“旧范围”。同一建筑的多个旧投入合并为一条记录，保留原范围和原建设点；移除后重新配置才转为整栋范围。新旧规则分数不宜直接比较。

迁移前原始存档备份到原键名加 `:before-building` 的本机存储项。旧的 `:before-spatial` 备份不覆盖。不同设备或域名的浏览器进度仍互相独立。

## 地图范围与来源

- 长安校区经南区核验后保留 41 个 OSM 建筑轮廓和 14 个校方资料补绘体块，共55个建筑组。原海天苑2号楼的13个相连部件合为一个建筑组，留学生公寓的3个相连部件合并；建筑数变化不代表删除这些楼翼。
- 依据校方总图、2025年底导览和2026年海天苑篮球场实景，补入海天苑运动场、航空宇航支撑学科创新中心；艺术教育中心与原活动中心作同址名称关联。运动场轮廓为近似补绘，内部场线与数量为示意。
- 修正南山苑地面覆盖，移除原矩形筛选误收录的校外机电楼；建筑、连接体与底座统一零标高，解决悬空。原始OSM校界保留在数据内，显示底座不作为地籍边界。
- 海天苑三期（4号楼）依2022年可研效果图、2026年移交航拍与OSM邻楼核对，补在1号楼北、留学生公寓西：双六层主翼、低连接体、中庭、白灰与蓝色立面。四期依校方明确的“二期西侧原农场”位置、现场与效果图复核：四条东西向楼翼，按2026年8月封顶后的在建阶段显示楼板/立柱、防护网、围挡及示意塔吊。美食广场依后勤部门开业报道，在餐厅北侧原绿化带补入单层玻璃餐饮空间。
- 新增三处的相邻关系经公开资料核对，边线、楼长、层高、连接体和施工设施仍为人工近似，不是米级摄影测量或竣工总平图。四期设计图只用于布局，不能当作已竣工状态。原2022年小球场移至历史数据，不冒充海天苑主运动场。
- 友谊校区新增 385 个建筑体块、79 段校内道路、6 个场地，按 OSM 主校园边界筛选。已去除两个旧轮廓与新轮廓完全重叠的问题，保留多边形孔洞。校方图中的西侧、南侧分离附属地块尚未全部纳入。
- 友谊校区参考 2021 年官方总图、2025 年国际学生指南及创新科技大楼官方竣工说明。公字楼、勇字楼等部分楼层由旧图估算；创新大厦分别表现 19 层北塔、23 层南塔、4 层裙楼，楼高按每层约 3.5 米换算，仍非实测。
- 窗格、楼层线、女儿墙、屋顶设备、绿化和运动场标线是表现性细节；选择建筑光伏后出现的屋顶组件是改造提案。细节采用批量实例绘制以控制模型开销。
- OSM 轮廓不是测量认证资料。校方总图未注明版本，在较早页面中已出现。模型不保证为最新竣工现状。
- 建筑高度、立面材质、树木位置均为表现性简化；绿化/光伏/照明/接驳是教学构想，不是现有设施声明。

## 项目结构

- `src/spatial.ts`：网格生成、选址约束、邻域传播、道路连通、正负协同、空间计算与存档迁移。
- `src/buildingPlanning.ts`：建筑分组、轮廓裁切、整栋措施、周边选址、预算和存档迁移。
- `src/buildingInterventions.ts`：在原模型上显示屋顶光伏、楼旁设施、线路和建筑高亮。
- `src/buildingImpact.ts`：所选单项措施的同情境反事实比较、建筑增量归因、正负分项。
- `src/impactOverlay.ts`、`src/ImpactSummary.tsx`：独立三维影响图层与可定位的建筑影响列表。
- `src/GridMap.tsx`：V 0.3 历史网格视图，V 0.4 不导入、不展示。
- `src/spatial.css`：建筑规划界面和移动端布局。
- `src/game.ts`：旧版规则、措施元数据及旧存档校验，供迁移和兼容测试使用。
- `src/CampusMap.tsx`：Three.js 地图、校区场景、标记、地标近景、大图与镜头。
- `src/buildingModels.ts`、`src/landscapeModels.ts`、`src/constructionModels.ts`：建筑立面、在建骨架、施工围挡/临设、运动场与植物细节。
- `src/campuses.ts`：校区配置、各自措施位置、来源和存档键。
- `src/data/campus.json`、`src/data/youyi.json`：两校区处理后的地图几何与来源标注。
- `src/App.tsx`：措施选择、A/B、结果、来源和规则界面。
- `scripts/prepare-map.mjs`、`scripts/prepare-youyi-map.mjs`：由原始 OSM 和参考资料重新生成几何数据。
- `tests/building-planning.test.ts`：整栋覆盖、中庭、小建筑隔离、楼群、周边设施、预算、迁移及可完成挑战。
- `tests/building-impact.test.ts`：增量归因、同单元邻楼隔离、收益/代价并存、站点连通传播、A/B/事件/预算边界及三维图层释放。
- `tests/spatial.test.ts`：位置差异、邻域范围、协同/冲突、路网断连、预算、重复覆盖、日照/天气、顺序无关性、旧存档迁移及两校区可完成挑战。
- `tests/game.test.ts`：旧版兼容计算与存档校验回归。
- `tests/campuses.test.ts`：跨校区存档隔离、措施坐标/建筑映射与共享参数一致性。
- `tests/changan-geometry.test.ts`：南区缺项回归、楼群合并、地面覆盖与实际三维网格落地高度。
- `scripts/browser-changan-audit.cjs`：海天苑片区/运动场近景、南山苑低角度、来源说明与手机视图检查。
- `scripts/browser-check.cjs`、`scripts/browser-campuses.cjs`：V 0.2 历史浏览器检查脚本，固定组合控件已被空间布局替换，不能用于验证 V 0.3。新版通过浏览器检查选格/实施、A/B、事件、校区存档、三维标记和手机布局。

## 当前边界

如需重新生成长安校区数据，先用 `python -m pip install --target .tools/geometry -r scripts/geometry-requirements.txt` 安装离线几何工具，再运行 `node scripts/prepare-map.mjs`。该流程每次从原始 OSM 快照重建、应用补绘与空间核验，不依赖上一次生成结果，也不向浏览器引入 Python。

本版完成可玩机制和地图场景。正式政策原文卡、学习测评、真实校园设施数据校核留待下一版。浏览器支持 WebGL 时显示三维地图，不支持时显示官方参考图，措施和对照仍可使用。进度只保存在当前浏览器；重要方案可导出备份。
