# 2030 校园实验室 · 西工大双校区

以西北工业大学长安校区和友谊校区为地图场景的绿色校园决策原型。所有预算、碳排放和体验数值均为教学设定，不代表学校实际数据。没有接入实时 AI，没有账号和远程业务服务。

## 参赛评审：先看这里

**你将扮演校园规划者，在有限的教学预算内，为建筑配置花园、慢行、节能等措施，观察影响，再比较两种方案。** 无需输入提示词或准备 API Key。

- **在线入口**：[打开 2030 校园实验室](https://1786518043.github.io/nwpu-campus-lab-2030/)。无需安装、登录或 API Key，使用浏览器直接打开。当前版本 V 0.8，新增自由探索手动预算；发布与验收记录见提交清单。
- **推荐体验设备**：电脑浏览器，较大屏幕便于同时观察三维地图与操作面板；手机可体验响应式界面。三维视图需要 WebGL，不支持时仍可通过建筑列表配置措施。
- **本地备用方式**：见下一节“运行”。这是网页工程，不能直接双击 `index.html` 运行，也不是独立的 `.exe` 程序。

### 第一次体验：约 3 分钟

以下路线对应 V 0.8。建议首次体验使用空白进度；已有进度时先导出，再按需点击“重新开始实验”（会清空当前校区方案、事件和 A，保留通关、图鉴历史、当前模式和探索预算）。

1. 选择 **长安校区**，在“校园行动手册”选择 **一处清凉**。保持默认常态情境。
2. 展开 **需要一点选址提示？**，点击 **云天苑B座 · 雨水花园**。页面会定位建筑并显示预览，此时尚未投入预算。
3. 在措施面板点击 **确认配置雨水花园**。观察剩余预算、热压力和“校园回声”；目标全部达成后，点击 **提交本关**。
4. 点击 **保存方案 A**，保留刚才的方案。选择任务 **绿荫上学路**，仍选云天苑B座，选择 **慢行路段** 并点击 **确认配置慢行路段**。观察协同发现提示，可打开“协同图鉴”。
5. 点击地图上方 **A/B 差异**，查看增加慢行路段后的变化，点击建筑查看分项。A 与 B 始终使用相同情境和预算。
6. 点击 **情境变化**，尝试 **持续高温** 或 **连续降雨**，观察两份完整方案重新计算的结果。控制台 **A/B 对照** 中可点击 **导出建筑对照**，下载 JSON 记录。
7. 切换到 **友谊校区** 再切回来，观察两个校区各自保存的方案。进度保存在当前浏览器，换设备、地址或无痕窗口不会自动同步。

### 想尝试更大的改造方案？

点击行动手册右上角的 **自由探索** → 在 **自由探索预算** 输入 **100–1000** 之间的整数（例如 `500`）→ 点击 **应用预算**。输入中的草稿不会改变方案，应用后 A/B 和措施预览立即使用同一预算重新计算。两个校区分别记住自己的预算，刷新后仍保留。

自由探索中的常态、高温、降雨和“预算收紧”均使用手动预算。点击 **继续任务** 会恢复任务预算：通常 100 点，“预算收紧”为 80 点。模式切换或调低预算均保留布局和方案 A；若出现超支，可移除措施或返回自由探索提高预算，超支方案不能保存为可行方案或提交任务。自由探索只显示参考目标，不记录任务通关，仍可收集协同图鉴。

### 作品亮点与 AI 使用说明

- **校园问题可体验**：用西工大双校区三维场景，把绿色校园建设中的预算、选址、协同与环境代价变成可操作的教学实验。
- **结果可解释、可复现**：措施先预览再确认；A/B 共用情境与预算；可查看规则和地图来源、导出方案及计算结果。
- **学习有路径**：任务关卡、模拟师生反馈和协同图鉴，引导体验者从一次小改造逐步理解综合决策。
- **AI 辅助创作**：开发过程中使用 **Codex 辅助编写代码、ChatGPT 整理规则**。作品运行时由确定性规则计算，不调用实时 AI 接口；“校园回声”是依据规则结果触发的模拟文案，不是真实师生意见或大模型即时回答。

地图数据 © OpenStreetMap contributors，采用 [ODbL 1.0](https://opendatacommons.org/licenses/odbl/1-0/)。建筑高度、未核验部分与设施表现为简化；预算和指标为教学设定。完整说明见下文“地图范围与来源”。

## 运行

### Windows 本地运行（备用）

准备 **Node.js 24 LTS** 和 **pnpm 11.25.0**；当前本机验证环境为 Node.js 24.19.0。首次安装依赖需要联网。源码解压后，在包含 `package.json` 的项目文件夹打开终端，依次运行：

```sh
npm install -g pnpm@11.25.0
pnpm install --frozen-lockfile
pnpm dev
```

终端出现地址后，打开 http://127.0.0.1:5173/ 。运行时保留终端窗口，结束时按 `Ctrl+C`。如果找不到 `node`、`npm` 或 `pnpm` 命令，请先完成对应安装并重新打开终端。端口被占用时以终端实际显示的地址为准。

已安装 Node.js 和项目依赖的 Windows 电脑，也可双击根目录的 `启动校园实验室.cmd` 启动并打开浏览器。**该脚本不会替你安装依赖**，不能保证在全新电脑上直接双击即用。脚本固定使用 5173 端口，如提示占用，请先确认已有服务是不是本项目。开发服务仅监听本机。

项目也可在具备上述 Node.js、pnpm 环境的 macOS/Linux 上使用终端命令运行，`.cmd` 脚本仅适用于 Windows；本次验收在 Windows 环境进行。

### 手机局域网预览

手机体验：双击 `手机预览校园实验室.cmd`，或运行 `pnpm preview:phone`。脚本先生成生产构建，再在电脑当前有默认网关的网卡地址上启动静态预览，显示类似 `http://192.168.31.129:4173/` 的链接。手机和电脑须连接同一 Wi-Fi，手机打开脚本显示的地址；`127.0.0.1` 在手机上指手机自身。电脑及预览进程须保持运行，换网络后重新启动以获取新地址。该入口不进行公网部署，不能通过蜂窝网络直接访问。

如同一 Wi-Fi 仍连接失败，检查 Windows 防火墙是否允许当前局域网访问 TCP 4173，以及 Wi-Fi 是否使用访客/设备隔离。手机预览脚本不自动修改防火墙或网络安全设置。局域网预览使用构建结果，代码更新后需重新运行。不同设备、不同地址的浏览器存档相互独立，可导出结果备份。

### 测试与生产构建

```sh
pnpm test
pnpm build
pnpm preview
```

`dist/` 为生产构建。GitHub Pages 发布流程见 `.github/workflows/pages.yml`：推送 `main` 后自动安装锁定依赖、执行测试、构建并部署；仓库 Settings → Pages 的 Source 应设为 GitHub Actions。更新是否上线以 Actions 的部署结果为准。本机文件修改不会自动推送。Vite 和参考图片使用相对于站点的路径，可部署在仓库子目录或域名根目录。

公网访问无需本机保持开机，各访问者的实验进度保存在自己的浏览器中。更换域名后旧地址的浏览器存档不会自动迁移，可在旧地址导出结果备份。此前的 Sites 配置保留在 `.openai/hosting.json`，GitHub 工作流不会更新或依赖该站点。

## 自由探索预算（V 0.8）

- **预算范围**：100–1000 整数建设点，默认 100。空值、小数、越界值不能应用；旧存档缺少该设置时默认 100，不影响已有措施、A/B 和学习记录。
- **统一计算**：当前 B、方案 A、单项措施预览、确认配置、地图侧栏、完整对照及导出采用同一有效预算。调整预算只影响可行性和剩余点数，不改变物理效果、措施成本、事件或布局。
- **任务边界**：任务仍使用事件预算（100/80）。自由探索不发放任务通关记录；回到任务模式后按原标准判断。图鉴可在自由探索收录，首次发现证据记下当时的探索预算，读取时按该预算重新校验。
- **存档与导出**：沿用独立的 `campus2030:play:v1:<校区>` 存档，新增 `explorationBudget`；建筑版本 3 和旧长安存档迁移保持兼容。导出增加 `mode` 与 `budget`（来源、有效预算、探索设置及规则标识）；自由探索导出的当前任务状态为空，历史通关保留。
- **重新开始与撤销**：重新开始清空当前校区布局、事件和 A，保留当前模式、探索预算和学习历史；撤销恢复建筑操作或事件，不回退探索预算设置。

`tests/exploration-budget.test.ts` 检查范围与兼容、预算不改变物理效果、采购/预览/A/B 一致性、学习证据及任务隔离。`node scripts/browser-budget.cjs` 检查真实输入、超过 100 点的配置、降低预算、导出、任务切换、事件、双校区、刷新、重置/撤销及 320 像素布局；同样支持 `CAMPUS_PREVIEW_URL` 和 `PLAYWRIGHT_MODULE_PATH`。

## 校园行动手册（V 0.7 起）

在原有建筑规划工作台上增加任务关卡、虚拟师生反馈与协同发现，不改变预算、指标、空间计算或 A/B 规则。没有接入运行时 AI。

- **四个任务**：一处清凉、绿荫上学路、接驳连起来、2030 综合挑战。关卡可自由切换，保留当前布局与事件；也可以点击「自由探索」切换为手动预算模式。任务始终检查当前 B 的完整结果，任务预算与布局有效且全部目标达成后，点击「提交本关」记录成果。历史通关与当前达标情况分别显示。
- **选址提示**：展开任务里的提示可定位校区内的示例建筑并选择措施，不自动配置、不扣预算。三个入门任务的提示方案和综合挑战均已在两个校区验证可完成。玩家也可以另选建筑。热压力下降采用花园所属建筑周边约 40 米范围的模拟需求加权值，与同情境空白方案比较，使用完整精度判定是否下降至少 1 点。
- **校园回声**：选中建筑后，三维地图会出现带学生、老师或后勤职工头像的聊天气泡，随镜头投影跟随建筑。多条反馈可翻页，有代价时显示「听听提醒」；可展开计算依据、收起为头像、点击楼名重新定位。窄屏自动限位并避让地图工具，展开大图同样可用。控制台保留完整反馈。内容依据热压力、雨水压力、出行、照明和改造贡献等实际计算触发；节能改造由后勤职工反馈。A 只使用 A 的计算，尚未确认的措施预览不会改变角色反馈，A/B 差异视图不显示单一方案气泡。噪声与光扰动单独显示，不被净收益掩盖；头像为本地矢量插画，角色文案不是实际师生意见。
- **协同图鉴**：绿荫步道、步步相连、两站成线、最后一段路。实际实施后，从原有引擎的正面协同结果自动收录；只收录可行的 B 方案，预览、单独查看 A、超预算或无效布局不会获得记录。图鉴保留触发方式、收益与代价，可定位当前参与建筑。首次发现记录与「B 正在触发」分别显示；收集不额外加分。
- **存档与复现**：行动手册独立保存在 `campus2030:play:v1:<校区>`，不修改版本 3 建筑存档及旧版迁移流程。每次通关和首次发现记录措施、旧实施范围（如有）、共同事件、规则版本及时间，读取时重新验证。导出的 JSON 增加 `learning`，包含历史证据和当前 B 的任务与协同状态。
- **重新开始**：清空当前校区布局、事件和 A；保留该校区的通关与图鉴历史，当前达标与触发状态重算。另一个校区的建筑方案、事件、A/B 和学习记录均不受影响。

`tests/campus-play.test.ts` 验证双校区可完成性、协同、事件/次序一致性、预算限制、记录校验与角色反馈。运行生产预览后，`node scripts/browser-play.cjs` 检查实际浏览器流程，默认地址 `http://127.0.0.1:4173/`，可通过 `CAMPUS_PREVIEW_URL` 改写；Playwright 路径可通过 `PLAYWRIGHT_MODULE_PATH` 指定。检查使用隔离浏览器存储，覆盖任务、预览、反馈利弊、A/B、导出、双校区、刷新、重置/撤销及手机布局；截图保存在 `test-results/play-*.png`。

`node scripts/browser-map-voices.cjs` 进一步检查地图头像聊天、反馈切换、收起/展开、计算依据、镜头跟随、A/B 与校区隔离及 320/390 像素手机布局；截图保存在 `test-results/map-chat-*.png`。

地图右侧的「当前措施」侧栏按建筑列出已配置项目、单项投入和方案预算，可直接定位措施、移除当前 B 的项目、撤销上一步或返回校园全貌。列表独立滚动，不带动页面和地图。宽地图为侧栏预留空间；窄地图显示可收起的抽屉，点击措施后返回建筑近景，大图同样可用。查看 A 时清单与预算使用 A 且只读；A/B 差异视图展示 B 底图清单，点击项目回到 B 的贡献视图。两个校区继续独立保存，规则与存档格式不变。`node scripts/browser-map-measures.cjs` 检查侧栏定位、移除/退回预算/撤销、长列表滚动、A/B 与校区隔离、大图、窄屏和超预算提示，截图为 `test-results/map-measures-*.png`。

## 建筑规划怎么玩（V 0.4 起）

保留原有 Three.js 精细校园作为唯一规划主视图。网格只参与后台运算，页面不展示格线、格子编号或选格操作。

1. 点击三维楼体，或搜索、选择建筑。所选楼体高亮，可近看立面、屋顶、中庭与施工状态。无法使用 WebGL 时仍可通过建筑列表配置。
2. 按整栋建筑选择措施。光伏、节能改造覆盖完整轮廓；同一 OSM 关系的多个体块，以及名称明确关联的教学东楼、海天苑大楼、启翔楼等楼翼统一作为一个实施单位。原始模型几何不改动。
3. 花园、照明、慢行和接驳归属于建筑，后台选择附近符合条件的开放地表或道路。不能占水体、球场、施工区；同一公共设施若已由邻楼配置，可共享服务，不能重复购买。
4. 确认前查看投入与边际效果。花园和慢行有协同，慢行与接驳可连通，照明和站点可能影响生态安静与宿舍；原有距离衰减、重复覆盖、天气与预算规则继续有效。
5. 保存建筑方案 A，再调整 B。两份方案共用事件和预算，切换 A/B 时三维设施同步显示；超预算方案保留但不能另存为可行方案。
6. 导出包含建筑名、建筑 ID、措施、实施范围、内部空间属性和计算结果的 JSON，便于复现。

任务模式的教学挑战保持：100 建设点内，同情境减排至少 2%、体验提高至少 1、模拟活动需求覆盖至少 12%；预算收紧为 80 点。两个校区均有经过测试的可行建筑方案。自由探索使用 100–1000 点手动预算，上述指标只作为探索参考目标。

## 建筑与内部空间计算

- `src/buildingPlanning.ts` 将完整建筑多边形与内部约 40 米单元做面积裁切并扣除中庭。小于单元的建筑也可以独立选择；相邻建筑共享内部单元时，仍按各自轮廓贡献分别计算建筑用能与减排。
- 每个建筑单位对应一个措施记录，不让用户逐格拼楼。关联楼翼作为同一单位，但原立面、连廊、屋顶设备与施工模型保留。
- 建筑节能和光伏成本采用体量函数：基础单价 × (0.45 + 0.55 × √(建筑面积 / 内部单元面积) + 0.06 × 模型高度)，四舍五入、最低 6 点。均为教学预算，非工程造价。
- 慢行选择楼旁相连的已有路段，最多覆盖四个内部路段单元，按 8 点/单元计价。花园选择距建筑边界约 60 米内可用地表；照明和慢行约 70 米、接驳约 80 米内匹配候选位置。这是可用位置近似，不是核验过的真实出入口。
- 花园影响半径约 120 米，慢行/照明约 80 米，站点约 100 米。影响随距离线性衰减，同类服务取较强值。接驳通过已有车辆路网寻路，不使用步道、台阶；未连通站点不产生服务。
- 接驳站点显示在最近的车辆道路中心线上，线路严格沿 `campus.json` / `youyi.json` 中已有道路折线连接，在相交处换路，按几何长度寻最短路；不再连接计算网格中心，不跨越道路缺口或近邻平行道路。预览、已实施和 A/B 使用相同线路。至少约 120 米的沿路间距才形成服务；每段运行用能为 `0.45 + (沿路长度 / 40 米 + 1) × 0.018`，与原直线路段标尺一致，弯路按实际折线长度计算。站点服务和环境影响保留原 40 米内部单元近似。
- 道路仍为公开地图的平面教学模型，未加入单行、限行、立交高程或实际运营条件，不代表可直接运营的接驳方案。本次仅修正寻路与显示，未改动地图来源或道路坐标。现有两校区布局、事件和 A/B 存档继续读取，线路与指标按当前道路重新计算。
- 每栋建筑先节能，再用光伏抵扣剩余用能。节能系数 0.65（高温 0.55）；光伏抵扣受日照代理与天气系数限制，不能把邻楼的剩余用能也一起抵扣。照明、线路运行另计耗能。
- 全校排放相对常态空白方案归一化；体验、压力和覆盖按模拟活动需求加权。覆盖表示体验改善至少 1 点或本地用能降低超过 8%，不是实际服务人数。
- 人流需求、日照、未识别空地比例、建筑高度和各种作用系数均为教学估算。没有地形高程或管网，不模拟真实汇水方向。固定输入和事件得到固定结果，次序不改变结果、事件不累计。

## 存档兼容

V 0.6 增加完整方案的三维 A/B 对照，继续使用同一套精细模型和版本 3 存档，不更改原有分数规则。

- 保存 A 后调整 B，点击地图上方的「A/B 差异」或控制台「A/B 对照」。地图以 B 的设施为底图，绿色楼体轮廓表示 B 更优，红色表示 B 更差，琥珀色表示不同分项各有取舍，灰色表示配置不同但当前指标无明显差异。原楼体、立面、中庭和施工状态保留，没有外部网格。
- 可切换综合利弊、体验净变化、负面代价、热压力、雨水压力、出行便利、本栋改造减排贡献。综合利弊逐项保留正负变化，不用总收益掩盖局部代价；负面代价分别计算噪声、光扰动和照明用能。
- 点击楼体、差异标签或下方建筑卡可定位并查看 A、B、B−A 的完整明细，以及本栋新增/移除的措施。明细优先展示当前指标和变化项；地图查看不修改实施位置。下方列表支持正面、负面、取舍和配置变化筛选。
- 两份完整布局在同一事件、同一预算下分别从初始状态重算，包含路网启用、邻域传播和措施协同。不是把单项措施预览相加。先用完整精度计算差值，再展示两位小数；绝对差小于 0.005 记作无明显差异。
- 周边环境沿用楼体及楼外约 40 米的需求加权评价范围，邻楼可能共享环境，不能逐栋相加。本栋改造减排贡献是移除该楼节能/光伏后增加的全校排放指数点，只归到措施所属楼，保留旧局部范围；它是边际贡献，不是可相加的逐楼碳账本。线路运行用能单列。
- 相同方案不显示差异高亮。超预算或布局冲突方案明确提示，仍可查看效果，但不能保存为可行方案。导出包含同情境逐楼对照结果。两校区的 A/B 和事件继续独立保存。

V 0.5 增加所选措施的三维影响预览，沿用 V 0.4 的分数和版本 3 存档。蓝色柔和光晕表示距离作用范围，建筑轮廓与标签分别用绿色（正面）、红色（负面）和琥珀色（利弊并存）解释增量影响，不展示计算网格。几何模型和来源不变。

- 新措施比较“当前方案”与“增加这一项”；已实施措施比较“移除这一项”与“保留这一项”。A 只分析 A 内已有措施，共用当前天气；预览不写入措施或预算。
- 两侧都从初始状态重算，所以包含花园与慢行、照明与花园、站点与宿舍的协同/代价和重叠收益递减。正负分项分别显示，净体验提高不会掩盖噪声、光扰动或用能代价。
- 范围半径直接使用空间引擎的参数，连通站点与末端慢行的间接启用区域也展示。孤立站点仅显示灰色潜在范围，无出行收益；线路运行能耗单列，不强行分配到邻楼。
- 屋顶和节能措施的新配置只归因到所选整栋建筑。同一计算单元内的邻楼不会被标成获得本栋屋顶改造。旧配置保留原范围并提示。
- 周边指标按建筑轮廓及楼外约 40 米范围内的模拟需求加权。周边用能展示该评价区域的相对变化；其他分项为模型指数。相邻建筑共享环境，不可把这些区域指标相加。图上连续光晕是作用范围示意，不是实测物理边界或工程预测。
- 点击影响标签或下方建筑卡可查看明细、定位邻楼，保留原措施选址。可隐藏影响恢复纯模型，也可一键查看影响全貌。

V 0.4 使用版本 3 的建筑存档，两个校区仍各自使用原键名。V 0.1–0.3 的措施位置、事件及 A/B 都会迁移：原实施范围保存在建筑记录的 `legacyCells` 内，按最近建筑归类，页面标记“旧范围”。同一建筑的多个旧投入合并为一条记录，保留原范围和原建设点；移除后重新配置才转为整栋范围。新旧规则分数不宜直接比较。

迁移前原始存档备份到原键名加 `:before-building` 的本机存储项。旧的 `:before-spatial` 备份不覆盖。不同设备或域名的浏览器进度仍互相独立。

## 项目结构

- `src/buildingPlanning.ts`：建筑分组、轮廓裁切、整栋措施、周边选址、预算和存档迁移。
- `src/buildingInterventions.ts`：在原模型上显示屋顶光伏、楼旁设施、线路和建筑高亮。
- `src/buildingImpact.ts`：所选单项措施的同情境反事实比较、建筑增量归因、正负分项。
- `src/impactOverlay.ts`、`src/ImpactSummary.tsx`：独立三维影响图层与可定位的建筑影响列表。
- `src/buildingComparison.ts`：完整方案同情境对照、建筑环境分项、屋顶改造贡献归属与利弊分类。
- `src/ComparisonSummary.tsx`、`src/comparison.css`：三维对照指标选择、建筑差值明细、可定位的筛选列表及手机布局。
- `src/GridMap.tsx`：V 0.3 历史网格视图，V 0.4 不导入、不展示。
- `src/spatial.css`：建筑规划界面和移动端布局。
- `src/game.ts`：旧版规则、措施元数据及旧存档校验，供迁移和兼容测试使用。
- `src/CampusMap.tsx`：Three.js 地图、校区场景、标记、地标近景、大图与镜头。
- `src/buildingModels.ts`、`src/landscapeModels.ts`、`src/constructionModels.ts`：建筑立面、在建骨架、施工围挡/临设、运动场与植物细节。
- `src/campuses.ts`：校区配置、各自措施位置、来源和存档键。
- `src/data/campus.json`、`src/data/youyi.json`：两校区处理后的地图几何与来源标注。
- `src/App.tsx`：措施选择、A/B、结果、来源和规则界面。
- `src/campusPlay.ts`：任务判定、协同发现、模拟角色反馈及独立学习存档；读取原有规则结果，不更改分数。

- `src/CampusPlayPanel.tsx`、`src/campusPlay.css`：任务手册、校园回声、发现提示、协同图鉴和手机布局。
- `scripts/prepare-map.mjs`、`scripts/prepare-youyi-map.mjs`：由原始 OSM 和参考资料重新生成几何数据。
- `tests/building-planning.test.ts`：整栋覆盖、中庭、小建筑隔离、楼群、周边设施、预算、迁移及可完成挑战。
- `tests/building-impact.test.ts`：增量归因、同单元邻楼隔离、收益/代价并存、站点连通传播、A/B/事件/预算边界及三维图层释放。

## 当前边界

如需重新生成长安校区数据，先用 `python -m pip install --target .tools/geometry -r scripts/geometry-requirements.txt` 安装离线几何工具，再运行 `node scripts/prepare-map.mjs`。该流程每次从原始 OSM 快照重建、应用补绘与空间核验，不依赖上一次生成结果，也不向浏览器引入 Python。

本版完成可玩机制和地图场景。正式政策原文卡、学习测评、真实校园设施数据校核留待下一版。浏览器支持 WebGL 时显示三维地图，不支持时显示官方参考图，措施和对照仍可使用。进度只保存在当前浏览器；重要方案可导出备份。
